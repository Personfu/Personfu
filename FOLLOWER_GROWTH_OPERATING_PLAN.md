# PersonFu / FLLC GitHub Follower Growth Operating Plan

This is the operating plan for making the PersonFu GitHub account worth following.

The problem is not lack of material. The problem is signal discipline. The account has enough raw material for a serious technical brand, but public visitors need a clean path: what to follow, what to star, what is alive, what is safe, and what connects to FLLC.

---

## Core objective

Turn GitHub from a repo dump into a weekly technical publication engine for FLLC.

A strong visitor should understand within 10 seconds:

1. Preston / PersonFu builds practical cybersecurity, OSINT, RF/hardware, and engineering systems.
2. FLLC is the business layer.
3. The best public work is easy to find.
4. The account ships new, useful public drops.
5. Advanced content has a paid/member path.

---

## What loses followers

- Too many uncurated forks with no explanation.
- High-risk offensive repos sitting beside professional business pages without context.
- AI-generated project names that sound intense but do not explain value.
- README files that do not tell people what the repo does, how to run it, or why it matters.
- No visible cadence.
- No screenshots, diagrams, demos, or outputs.
- Claims that feel bigger than the evidence shown.

---

## What gains followers

- A clear weekly drop rhythm.
- A handful of pinned flagship repos that look alive.
- Public reports with sources and defensive outcomes.
- Hardware/RF build notes with photos, diagrams, and lawful framing.
- Engineering logs that prove real work: telemetry, data, design, testing, failure notes.
- Clear split between free content, paid content, private source, and controlled references.
- Repo READMEs that explain purpose, status, setup, screenshots, roadmap, and boundaries.

---

## Pinning strategy

Use pinned repos as the storefront. The visitor should not see randomness first.

Recommended pin order:

1. `Reports` — public OSINT / defensive briefing archive.
2. `FurulieLLC` — company platform and website source, if public visibility is intentional.
3. `CyberFlipper` — hardware-security / RF showcase.
4. `CISSQLexe` — SQL education product demo.
5. `CVE-Intelligence` — vulnerability prioritization and defensive intelligence lane.
6. `NASA-ASCEND-Website` or `NASA_ASCEND_UNITY` — engineering credibility and STEM evidence.

If `FurulieLLC` should stay private, replace it with `GovINT`, `CyberCity`, or the strongest NASA ASCEND repo.

## Weekly publishing loop

### Monday — OPEN-CLASSIFIED Report

Repository: `Reports`

Minimum viable drop:

- One public source-backed briefing.
- One executive summary.
- One defensive action checklist.
- One FLLC upgrade path.

### Wednesday — Build Log

Repository: profile repo, `FurulieLLC`, `CyberCity`, `CyberWorld`, or education repos.

Minimum viable drop:

- What changed.
- Screenshot or file link.
- Why it matters.
- What ships next.

### Friday — Hardware / RF Bench

Repository: `CyberFlipper`, `HackRF-Treasure-Chest`, NASA telemetry repos, or hardware notes.

Minimum viable drop:

- Lab-safe concept.
- Tool/device context.
- Legal/ethical boundary.
- Build note or diagram.
- Defensive learning outcome.

### Weekend — Engineering Log

Repository: NASA ASCEND, data analysis, Unity/simulation, or FLLC engineering pages.

Minimum viable drop:

- Mission or experiment context.
- Data, chart, screenshot, or architecture note.
- What worked.
- What needs fixing.
- Public-safe next step.

## Repo README baseline

Every repo that stays public should eventually have:

```text
# Project name

One-sentence purpose.

## Status
Active / preview / archived / fork reference / private candidate.

## Why it matters
Business, education, engineering, or defensive security value.

## What is included
Short list of major files/features.

## Quick start
Install/run/view instructions, if applicable.

## Screenshots or outputs
Image, demo link, report sample, chart, or terminal-safe output.

## FLLC lane
Free showcase / paid member path / private source / controlled reference / archive.

## Boundary
Legal, ethical, safety, or public-source framing.
```

## Content quality test

Before publishing a drop, ask:

1. Would a stranger understand why this matters?
2. Is there a source, screenshot, chart, demo, or clear output?
3. Does this make FLLC look more credible?
4. Is it lawful and defensive?
5. Does it avoid fake authority or overclaiming?
6. Is there a next step for free readers and paid members?

If the answer is no, it is not ready.
